# 正式课程周期课表实时对接方案（仅方案，未实施）

## 数据发布关系

排课系统是正式课表来源；vcd-course.designdaily.cn 是只读展示端。管理员发布后产生不可变快照，展示端读取明确标记为当前运行周期的最新正式版本。草稿、教师预选及未发布修订不进入展示数据。

## 接口与刷新

- 建议接口：GET /api/public/timetables/current，返回当前运行周期列表及各周期 snapshot_id、revision、published_at、updated_at、schema_version。
- 周期由管理员明确指定当前运行状态及起止时间，不采用“ID最大”或“最后发布”作为判断条件。同一学期多个专业周期可并存。
- 明细接口：GET /api/public/timetables/{cycle_id}。只输出已发布快照，包含周期日期、周数、考试周及课程任务。
- 网站加载时请求接口，页面可见时每30秒检查更新，重新获得焦点时检查一次；支持ETag/If-None-Match和304，版本变化后整体原子替换课表。
- 对真正秒级更新有要求时增加SSE版本通知；通知只携带周期/版本，客户端随后重新获取完整快照。
- 首次失败显示不可用；已有缓存时保留最后成功版本，标明更新时间与离线状态，不能把旧缓存称为最新数据。

## 展示数据契约

稳定标识使用cycle_id、snapshot_id、task_id、course_id、class_id、teacher_id、room_id；名称仅用于显示，不用于关联。

字段包含学年/学期、年级、专业代码及名称、班级、课程名称与编码、六类课程类型、三类课程性质、学分学时、教师姓名、地点、start_week/end_week、normal/tail节次、考试周。人数明确区分班级人数与实际选课人数；未填写显示待统计。缺节次和地点显示待安排，不猜定。

专业名称映射由编码管理，兼容参考网站旧显示名称；本科/研究生通过培养层次和学制区分，不共用固定八学期毕业判断。

## 部署与权限

优先在参考网站同源反向代理 /api/timetable，转发到排课后端的专用只读出口；不把管理员令牌或后端密钥写进网页。后端必须是可访问的正式HTTPS服务，不能依赖本机127.0.0.1开发服务。

如直接跨域读取，显式放行https://vcd-course.designdaily.cn，限制方法为GET，实施速率限制和缓存。若展示数据不适合公开，则网站经登录鉴权并按范围查询，不能仅靠CORS保护数据。

公开字段采用白名单，排除教师联系方式、账号、申报意愿、审核记录、个人画像和内部备注。首次发布到外站前确认展示范围。

## 验收与实施前置

1. 取得参考网站源码、部署方式和正式后端地址；确认网站公开范围。
2. 完成周期选择、数据契约、名称映射与兼容测试，再修改参考网站内嵌DATA读取逻辑。
3. 核对两端同一snapshot_id下课程数、班级、教师、地点、周段、节次与考试周完全一致。
4. 发布新版本30秒内更新；未发布修订不影响展示；网络失败不清空旧课表；恢复后自动追上新版本。
5. 测试多周期、历史周期、撤回/归档、权限及缓存失效。当前方案没有执行接口开发、跨站同步或线上部署。
