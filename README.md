# AI 驱动的一体化智能排课平台

面向学院分阶段授课管理的排课项目，采用 FastAPI + React 前后端分离架构。当前主流程为：**培养方案导入 → 管理员编排全学院课程周段、考试周与地点 → 教师填报意愿 → 系统匹配 → 人工审核与调剂 → 发布与导出**。

排课周期默认面向全学院所有年级与专业统一设置，系统按入学届次与学期推算各专业对应的培养方案学期；考试周可按年级分别配置，三、四年级可设置为无考试周。项目后端仍保留遗传算法排课、冲突检测与历史课表接口，前端已不再提供旧版排课入口。新版教师匹配采用评分与硬约束校验，需管理员审核，不代表遗传算法全局最优求解。当前为本地可运行版本，尚未完成真实学院数据、生产并发和部署验收。

## 当前功能

| 模块 | 已实现内容 |
| --- | --- |
| 基础数据 | 班级、教师、课程、教室维护及 CSV 导入 |
| 培养方案 | CSV/XLSX/DOCX 导入、预览、版本激活；保留原始字段、源文件和哈希 |
| 课程库同步 | 生效方案同步标准课程库，重复同步不重复新增；共享课程保留多个专业归属 |
| 全学院排课周期 | 一个周期覆盖全学院所有年级与专业；按届次与学期自动计算各专业对应的培养方案学期，班级默认全部纳入，可增删教学组 |
| 管理员阶段排课 | 教学组为纵轴、周次为横轴，拖放课程安排起始周与持续周数；课表下方可增删班级条目；通过“设置节次与地点”配置可选节次、尾段节次及教室 |
| 考试周设置 | 在课表编排页按年级点选考试周并保存；未配置沿用最后一周，全部取消表示该年级无考试周；已发布周期冻结；考试周禁止排课 |
| 教师个人资料 | 本人维护专业方向、领域、擅长课程；与管理员核实的团队、曾授课程和容量记录区分来源；教师管理页只读展示所属课程组与专业课程负责人 |
| 教师选课 | 按学年、学期、专业浏览阶段总表，跨专业预选、草稿保存；各管理员周期独立提交；不维护志愿顺序 |
| 课时与工作量 | 任务只设教师名额与人数上限，实际人数在选课结束后回填；预估课时按 25 人基数统一估算，管理员确认后按真实人数、真实授课周与尾周课时计算个人工作量 |
| 匹配与审核 | 系统自动匹配后实时生成全学院全局课表，卡片显示申报教师人数与姓名，管理员可手动调剂；五项匹配权重可逐项调节，资料版本变化后重新匹配 |
| 发布与归档 | 发布前硬约束检查（周段、考试周、地点容量、教师冲突）；节次为可选项；提交记录、匹配批次、来源材料、审计与发布快照不可变 |
| 课表导出 | 发布快照导出 XLSX、学院模板 Word；周次数量按周期设置，考试周按年级显示；旧课表接口仍支持 Excel/PDF 导出 |
| 旧版排课 | 后端保留遗传算法生成、版本管理、筛选与冲突检测接口；前端旧版页面已移除 |
| 访问控制 | JWT 登录；按 AccountGrant 功能与范围授权，教师身份通过 TeacherBinding 绑定 |

### 新流程的业务规则

- 教师必须完善专业方向、领域和擅长课程，才能保存预选或提交；前后端均检查。
- 开放填报前，管理员必须落实课程周段和有效地点；周内节次为可选，未配置时也能开放与发布，配置后则校验实际学时与时间冲突。教师意愿不占据名额，也不修改学院预设时段。
- 全学院周期未绑定单一专业或年级，所有班级默认纳入；各专业的培养方案学期按入学届次与周期学期推算（如 2026 级在 2026—2027 第 2 学期对应第 2 学期）。
- 考试周按年级（或教学组）分别设置：未配置时沿用最后一周为考试周；把某年级的周次全部取消即表示该年级没有考试周；已发布周期不可修改。课程周段、发布校验和导出都按年级解析考试周，考试周内不能排课。
- 已配置节次时，同一教学组每周最多两门课、每天最多一门；保留节次不计入授课学时。
- 按学年筛选、分学期浏览；仍以管理员创建的周期分别保存和提交，不合并为全年一次申报。每周期最多五项、至少 `min(3, 任务数)` 项。
- 课程任务只设定教师名额与人数上限，不预设实际学生数；实际人数在排课完成、学生选课结束后由管理员回填，并受人数上限与教室容量校验。
- 匹配默认权重：团队 40、方向 20、领域 15、曾授 15、容量 5（合计 95）；管理员可在“匹配与审核”中逐项调整，综合分满分随权重合计变化。教师不维护志愿顺序，选课顺序不参与评分。擅长课程命中独立展示，同综合分时优先；高分不能豁免硬约束。
- 教师工作量以管理员确认并锁定的授课安排为准：基数按 25 人计 1，每增加 1 人增加 0.02（不足 25 人仍按 1）；多教师授课按各自实际授课周数分配课时；课程尾周课时少于其他周时按真实尾周课时计算；毕业设计按 12 课时/生、毕业论文按 8 课时/生；选课阶段的预估课时统一按 25 人基数计算，不显示真实金额。
- 培养方案无正式课程代码时使用标明的 `SYS-` 内部编号。缺学期、零学时、占位及同名同学期重复记录保留待核查，不自动排入。

详细流程与范围见 [PLANNING_WORKFLOW.md](PLANNING_WORKFLOW.md)。

### 近期变更

- 排课周期改为全学院全局设置，覆盖所有年级与专业；系统按届次与学期自动匹配培养方案。
- 新增按年级配置考试周：课表编排页可直接点选周次，未配置沿用最后一周，全部取消即该年级无考试周；周段校验、发布校验与 Word/Excel 导出统一遵循。
- 周内节次改为可选项，发布排课周期不再强制校验节次；已配置节次时仍校验学时、地点与教学组冲突。
- 教师工作量拆分预估与真实两部分：预估统一按 25 人基数，真实工作量在管理员确认授课安排后计算，支持多教师按周分配、尾周真实课时及毕业设计/毕业论文按生计酬。
- 匹配与审核支持五类权重的逐项调节，自动匹配后可查看带申报教师人数与姓名的全学院全局课表并手动调剂。
- 管理员可在课表下方直接增删班级条目；非草稿阶段新增班级不会自动生成课程任务。
- 教师管理页的“分配课程”改为只读展示所属课程组与专业课程负责人，不再勾选分配。
- 前端移除旧版工作台、排课执行、冲突、约束、报表与注册页面，保留数据管理、排课周期计划、匹配与审核、历史课表及教师端功能；后端旧接口仍可访问。
- 旧版课表查询、冲突检测及导出未指定版本时统一取最新版本，避免混合多个历史方案。
- 冲突统计按周处理，避免将不同周的课时累加为同一天超载；生成结果补齐容量等冲突检查字段。
- 遗传算法接入启用的约束配置与权重；同一课程的班级、教师分配保持一致。
- 共享课程合并专业归属，自动生成的内部课程代码区分培养方案范围。
- JWT 密钥支持环境变量配置；`DEBUG=false` 时必须提供密钥；仅开发模式未配置时尝试在 `backend/data/jwt_secret.key` 持久化随机密钥。

以上描述对应当前 `main` 分支代码。

## 技术与环境

| 层级 | 技术 |
| --- | --- |
| 后端 | Python、FastAPI、SQLAlchemy、Pydantic、Uvicorn |
| 数据库 | SQLite，默认 `backend/data/scheduling.db` |
| 算法与分析 | NumPy、scikit-learn；旧版遗传算法与新版教师评分匹配 |
| 前端 | React 19、TypeScript 6、Vite 8、Ant Design 6、Recharts、@dnd-kit |
| 文件处理 | openpyxl、ReportLab；学院 Word 模板保存在后端模板目录 |

本机已使用 Python 3.12 和 Node.js 25。前端测试依赖 Node 原生 TypeScript stripping，建议使用相同环境；旧自述中的 Node.js 18 不适用于当前工具链。具体依赖见 [backend/requirements.txt](backend/requirements.txt) 与 [frontend/package.json](frontend/package.json)。

## 本地启动

### 获取项目与准备环境

```bash
git clone https://github.com/velophot-del/super-robot.git
cd super-robot
```

首次安装时：

```bash
cd backend
python3.12 -m venv .venv
.venv/bin/python -m pip install -r requirements.txt
```

在另一个终端进入项目的 `frontend` 目录：

```bash
npm ci
```

已有 `backend/.venv` 和 `frontend/node_modules` 时可直接启动，无需重复安装。

### 启动服务

在 `backend` 目录运行。先在当前终端设置密钥；本地临时运行可生成随机值（重开终端后需重新设置，令牌随密钥更换而失效）。正式使用应通过环境变量提供固定的私密值：

```bash
export SECRET_KEY="$(.venv/bin/python -c 'import secrets; print(secrets.token_urlsafe(48))')"
```

```bash
DEBUG=false .venv/bin/python -m uvicorn app.main:app --host 127.0.0.1 --port 8000
```

在 `frontend` 目录运行：

```bash
npm run dev -- --host 127.0.0.1 --port 5173 --strictPort
```

浏览器访问 `http://localhost:5173`。前端 API 默认请求 `http://localhost:8000`；使用 `localhost` 页面地址以匹配当前后端 CORS 设置。服务仅绑定本机回环地址。

- API 文档：`http://localhost:8000/docs`
- 健康检查：`http://localhost:8000/api/health`
- 启动自动创建数据库表；默认数据库位置相对于 `backend` 工作目录。
- 执行后端命令时显式设置 `DEBUG=false`，避免宿主环境中的同名变量导致配置解析失败。

### AI 排课分析（可选）

管理员点击左侧底部的齿轮「AI 设置」，选择服务商（DeepSeek、通义千问、月之暗面、智谱、自定义 OpenAI 兼容或 Anthropic），填写 API Key 后保存即可。

- 「课程表编排」页的「AI 排课分析」会基于当前周期的任务、教师、地点与考试周数据生成风险和建议。
- 「匹配与审核」页的「AI 排序并自动落位」会先读取当前匹配权重与候选评分，由模型重新排序候选后自动落位；落位前仍执行教师意愿、回避与容量校验。未配置、调用失败或结果无法解析时按规则排序落位。
- 未配置服务、密钥无效、超时或服务异常时，自动回退到规则分析，功能不受影响。
- 密钥使用 `SECRET_KEY` 派生的密钥加密后保存在数据库；接口只返回掩码，不会下发到浏览器。更换 `SECRET_KEY` 后需要重新填写。
- 也可通过环境变量 `ANTHROPIC_API_KEY` 使用 Anthropic（数据库未配置时的回退）；`ANTHROPIC_MODEL`、`ANTHROPIC_BASE_URL`、`AI_TIMEOUT_SECONDS` 可选。
- 接口 `GET/PUT /api/ai/config`、`POST /api/ai/config/test`、`POST /api/planning/plans/{id}/ai-review` 仅管理员可用。

### 登录与授权

首次运行可在 `backend` 目录创建管理员种子账户（交互式输入密码，重复执行不会覆盖已有密码，也不认领同名普通账号）：

```bash
DEBUG=false .venv/bin/python -m app.seed_admin
```

该账户会获得 `admin`、`review`、`publish` 三项全局授权。普通账号注册接口仍保留，但前端不再提供注册页；新账号不会自动获得管理或教学权限，也不按旧角色标签自动提权。真实账号需要管理员明确授予功能和范围；教学功能还需绑定教师。

以下命令在已设置 `SECRET_KEY` 的后端终端执行，替换实际 ID，仅预览、不写入：

```bash
DEBUG=false .venv/bin/python -m app.access_cli --user-id 1 --capability teaching --scope self --teacher-id 1
```

核对账号、教师与范围后添加 `--apply` 才会写入。支持的功能包括 `admin`、`teaching`、`lead`、`review`、`publish`，详见 [backend/app/access_cli.py](backend/app/access_cli.py)。

### 隔离演示

免登录身份切换入口为 `/debug`，默认关闭。启用时必须使用专用演示数据库，并同时设置相同的 `DATABASE_URL` 与 `DEBUG_DEMO_DATABASE_URL`，另设 `DEBUG_DEMO_MODE=true`。演示操作会修改演示库；不得连接正式数据库。

完整命令、虚构数据准备和身份切换说明见 [DEBUG.md](DEBUG.md)。文档中的临时数据库路径是本机示例，新克隆项目不包含该数据库。

## 当前限制

- 多教师共同授课目前只按各自授课周数分配课时，尚无按分段、分组、协作模式的独立分工与学时核算。
- 教师直接调课、开放计划修订/解锁、退回重报与通知尚未实现。
- 节假日、调休及周末校历尚未接入；真实学生名单完整性需管理员保障。
- 真实账号授权目前通过 CLI，尚无后台授权界面；跨资源统一导入预览与提交事务仍待完善。
- 考试周按年级手工配置，尚未与校历或教务系统自动同步。
- 培养方案 DOCX 适配现有学院版式，不代表支持任意院校格式或扫描件 OCR。
- 学院 Word 导出复用模板并从发布快照生成；尚未完成桌面 Word 逐页视觉验收，不能保证像素级一致。
- 尚未完成真实业务数据、生产并发及部署验收；自动排课结果仍需核查，不能将算法得分视为全局最优或零冲突证明。
